# 合合2048 · 微信小游戏首版

暂定名称：合合2048。版本：0.1.0。开发方式：原生 JavaScript + Canvas 2D。

工程包含可导入微信开发者工具的源码，以及使用同一逻辑、同一绘制代码的浏览器试玩入口。
当前状态是可试玩原型，尚未完成微信真机验证、资质备案和平台审核，未发布上线。

## 立即试玩

在本目录执行：

```powershell
npm start
```

打开 <http://127.0.0.1:2048>。无须安装 npm 依赖。

- 手机上滑动棋盘；电脑方向键或 WASD 移动，也支持鼠标拖动。
- U 撤回、H 玩法、R 重新开始，Esc 关闭普通弹窗。
- 4×4 棋盘，90% 概率生成 2、10% 生成 4。
- 每次有效移动后生成一个数字；每个方块每步至多合并一次。
- 合出 2048 可继续挑战；无有效移动时显示结束页。
- 每局有 3 次撤回机会，每次只撤回上一手，撤回时恢复新增方块出现之前的状态。
- 自动保存棋盘、得分、最高纪录、撤回次数和震动设置；重开保留最高纪录。
- 每天进入可领一次「撤回 +1」，只记在本机，不需要分享，也不需要联网。
- 动画期间暂不处理新移动，避免滑动与棋盘状态不同步。

## 导入微信开发者工具

1. 在[微信公众平台](https://mp.weixin.qq.com)注册小程序账号，服务类目选择「游戏」，注册后在后台「开发 → 开发管理 → 开发设置」取得 AppID。
2. 小游戏类目和个人主体的能力有差异（例如虚拟支付受限），主体类型要在注册时一次选对。
3. 安装微信开发者工具（稳定版）。本工程不依赖 Cocos / Unity / Laya，工具里选择「小游戏」项目类型即可，不需要引擎转换插件。
4. 将实际 AppID 填入 `minigame/project.config.json` 的 `appid`。目前为空，没有伪造 AppID。
5. 在开发者工具导入 **本项目的 minigame 文件夹**；`compileType` 已设为 `game`，入口为 `game.js`。
6. 导入时 AppID 一栏点「使用测试号」，从你账号下的小程序 / 小游戏里任选一个作为调试用的 AppID——本地调试不影响该 AppID 的线上内容。导入后工具会把 AppID 写回 `project.config.json`，此后即可用命令行自动打开（命令见下节）。
   - 如果测试号列表为空，说明账号名下还没有任何小程序 / 小游戏，需要先在公众平台注册并获取 AppID。
   - `project.config.json` 里不要手写 `touristappid` 之类猜测的值，微信会直接报「不存在此 AppID (code 10)」。
6. 编译后在模拟器检查显示、触摸、胜负弹窗和切后台存档。
7. 点击「预览」，用微信扫描二维码，在真机上验证；真机才能验证安全区、分享面板和性能表现。
8. 上传版本后在后台版本管理提交审核；审核通过后再发布。

`minigame` 是唯一需要上传的代码目录；`preview`、`tests`、`tools`、`artifacts` 不应导入小游戏包。

## 微信能力与范围

- 使用 `wx.createCanvas`、`wx.onTouchStart/End/Cancel`、`wx.get/setStorageSync` 和 `wx.onShow/onHide` 生命周期。
- 窗口信息优先用 `wx.getWindowInfo`，旧版本基础库回退到 `wx.getSystemInfoSync`；安全区由 `safeArea` 与屏幕高度推算。
- `wx.onWindowResize` 的回调数据在 WeChat 中为 `res.size.windowWidth / res.size.windowHeight`，这里同时兼容扁平写法。
- 入口同步注册 `wx.onShow`，冷启动用 `wx.getLaunchOptionsSync` 兜底，热启动以最新 `onShow` 为准。
- 分享使用 `wx.shareAppMessage`（「关于」页按钮）与 `wx.onShareAppMessage`（右上角转发菜单），共用同一标题；`wx.showShareMenu` 用于显示转发菜单。
- 每日奖励完全走本机 `wx.setStorageSync`，不联网、不需要服务端，**与分享完全解耦**，所以不构成利益诱导。
- 宿主要是不支持分享能力，相关入口自动隐藏，浏览器预览同理。
- 本版无广告、无内购、无登录、无服务端、无用户自定义输入和联网排行榜。
- 游戏源码没有上传个人信息的请求。微信宿主本身的数据处理须在正式隐私政策中如实说明。
- 存档与成绩仅在本机保存，清理缓存会清空；若后续接排行榜或商业化奖励，需要补充可信服务端校验。

## 分享与奖励：为什么这样设计

本版最早的设计是「分享给好友 → 本局撤回次数 +1」。这与《微信小程序平台运营规范》5.1「滥用分享行为」正面冲突，已在实现阶段修正：

- 规范禁止以「分享后无需互动或无需深度互动即可获得利益」的方式诱导分享，利益明确包含道具、积分、虚拟奖品等。
- 官方违规案例点名的情形就是「分享即获得一次续命机会 / 积分 / 金币」，与「分享即得撤回次数」完全同构。
- 还可能同时命中「通过利益诱导分享至群或好友」「分享收益非即时获得」。处理规则是限制活动页面、限制分享能力直至下架。

技术上这条路也不成立：微信没有可靠的「分享已完成」回调，`wx.shareAppMessage` 的 `success` 只代表转发面板流程走完，不保证卡片送达或被拆开，拿它发奖既不准确，也更容易被认定为诱导。

所以本版做了两件事：

1. **每日奖励完全本地化**：每个北京时间自然日进入后可领一次「撤回 +1」，只读写本机存储，不联网、不需要服务端，**与分享彻底解耦**（`openDaily` / `claimDaily`）。
2. **分享不带任何利益**：入口放在「关于」页，只是把游戏转发出去（`shareNow`），成功与否只给提示，不发任何东西。

后续维护请不要改回去：只要奖励变成「分享之后才能得到」，无论叫续命、道具还是抽奖机会，都属于同一类违规。真要做拉新玩法，应让被分享者产生真实互动并由服务端记录，单机存档无法自证。

由于本版本不请求任何个人信息，隐私侧压力较小，隐私合规草稿见 `docs/privacy.md`。条款原文见下方官方参考。

## 上线前必须完成

- [ ] 确认最终游戏名称、开发者主体、图标与简介；名称需与软著对应。
- [ ] 取得对应游戏的计算机软件著作权登记证书，并在后台完成资质填写。
- [ ] 完成小程序（工信部）备案；流程在公众平台提交，由平台代为申报，周期以管局为准。
- [ ] 按后台当前要求完成游戏备案、自审自查报告等适用材料。
- [ ] 在后台提交《用户隐私保护指引》，并配置可公开访问的隐私政策链接（草稿见 `docs/privacy.md`）；勾选项必须与代码行为一致，本版不收集任何个人信息。
- [ ] 填写真实的运营者信息、客服联系方式。
- [ ] 在开发者工具和 Android / iOS 真机验证，包括刘海 / 安全区、不同屏幕、切后台与分享面板。
- [ ] 确认平台要求的适龄提示、实名与防沉迷等适用要求并完成所需接入；本原型尚未处理这些平台审核事项。
- [ ] 上传测试版本，检查控制台日志、包体积（以后台显示的小游戏包体限制为准）和无网运行。
- [ ] 版本提审通过后执行发布。

注册开发者账号并不代表已经完成上线资质。以上以后台实际审核要求为准，不承诺仅凭源码即可通过审核。

## 软著费用与使用规则

可以自行向中国版权保护中心申请；软件著作权登记行政收费已停征，代理服务费是选择委托办理时的费用。
需要用本游戏真实完成的源代码、说明文档和身份 / 主体证明材料申请，不应购买无关游戏的证书。
软著权利人应与小游戏账号主体一致，且不要把同一证书套用到多款游戏；名称或权利人变化时，需另行核实登记与平台资质要求。

## 验证和打包

```powershell
npm test
npm run pack
```

测试覆盖合并、方向、一次合并限制、无效移动、死局、2048 胜利、继续挑战、撤回、存档校验、随机棋盘数值守恒、每日奖励每个自然日一次、**分享成功与失败均不发放任何奖励**，以及无 DOM 的微信入口启动（含 `onWindowResize` 与右上角分享卡片）。

浏览器检查脚本 `tools/verify-browser.cjs` 需要 Playwright 和 Chromium；测试 keyboard、画布按钮、滑动、撤回、重载存档、弹窗、小屏，并将截图保存到 `artifacts`。

打包生成 `dist/hehe2048-0.1.0.zip`，解压后在开发者工具导入其中的 `minigame` 目录。
